# Build a 2D Roguelike in Godot — Course Outline

This prototype ("The Last Forge") is structured so it can be taught as an
incremental build. Each lesson adds one self-contained system and ends with a
playable checkpoint. File references point at where each concept lives.

> Engine: **Godot 4.7** (mobile renderer). Main scene: `TitleScreen.tscn` →
> `Main.tscn`. Code in `scripts/`, scenes in `scenes/`, audio in `audio/sfx/`.

---

## Module 0 — Project setup
- Create the project, import the Kenney tiles in `Assets/`, set the window size.
- Configure the **Input Map** (`project.godot` `[input]`): `move_*`, `dash`,
  `quick_attack`, `heavy_attack`.
- **Checkpoint:** project opens, input actions exist.

## Module 1 — The player: movement, aim, dash
- `PlayerController.gd` + `Player.tscn`: `CharacterBody2D`, `move_and_slide()`,
  normalized WASD, aim the `WeaponPivot` at the mouse, dash with i-frames.
- `PlayerCamera.gd`: smooth follow.
- **Checkpoint:** walk, aim, and dash around an empty scene.

## Module 2 — A reusable damage system (components)
- `HealthComponent.gd`, `HitboxComponent.gd`, `HurtboxComponent.gd`.
- Teach the rule: **the Hurtbox is always the detector**; hitboxes are passive.
- Collision layers (1=World … 8=Pickups) — see `project.godot`/scene files.
- **Checkpoint:** a test dummy takes damage and dies.

## Module 3 — Attacks & game feel ("juice")
- `WeaponController.gd`: quick slash + heavy cleave state machine, hitbox
  sizing, swing/slash FX.
- `Juice.gd` + `shaders/flash.gdshader`: hit flash, impact particles, floating
  damage numbers.
- `GameManager.gd`: hit-stop (`Engine.time_scale`) and camera shake (trauma).
- **Checkpoint:** hitting things *feels* good (flash, shake, hit-pause).

## Module 4 — Enemies & AI state machines
- `EnemyBase.gd` (shared state machine + telegraphs) and inherited scenes:
  `GruntEnemy`, `ChargerEnemy`, `CasterEnemy` (+ `Projectile.gd`).
- Teach telegraph → attack → recovery and readable danger.
- **Checkpoint:** fight the three core enemies.

## Module 5 — The room loop
- `RoomController.gd`: spawn a wave, track living enemies, lock the room,
  show "Room Cleared".
- `HUD.gd` + `Main.tscn` UI: health bar, status banner.
- **Checkpoint:** clear a room of enemies.

## Module 6 — The corruption hook (upgrades)
- `UpgradeManager.gd` (data-driven dict of upgrades), `UpgradeCard.gd` +
  `UpgradeCard.tscn`.
- Corruption tiers and their damage-dealt/taken multipliers in
  `PlayerController.gd`; weapon visuals in `WeaponController.set_corruption_level`.
- **Checkpoint:** clear room → pick one of three cards → corruption rises.

## Module 7 — Audio
- `AudioManager.gd` autoload + `default_bus_layout.tres` (Master/SFX/Music).
- Placeholder SFX generated by `tools/generate_sfx.py` into `audio/sfx/`.
- Wire `AudioManager.play("…")` into attacks, hits, deaths, pickups, flow.
- **Checkpoint:** the game has sound; swap in real audio later.

## Module 8 — Procedural rooms
- `DungeonRoom.generate(depth)`: random size + interior pillars + colliders,
  TileSet built in code from the atlas.
- `RoomController` descends room→room with depth-scaled waves.
- **Checkpoint:** every room is a fresh layout.

## Module 9 — Pickups & loot
- `Pickup.gd` + `HealthPickup.tscn` / `CleansePickup.tscn`; drops on enemy death
  via `RoomController._maybe_drop`.
- **Checkpoint:** kills sometimes drop heal / corruption-cleanse pickups.

## Module 10 — More content (extend the data)
- New enemies via inherited scenes: `BruteEnemy`, `SkitterlingEnemy`.
- New upgrades: just add dictionaries to `UpgradeManager._defs`.
- **Checkpoint:** deeper rooms introduce new threats and choices.

## Module 11 — Framing the run
- `TitleScreen.tscn`/`.gd`, run stats in `GameManager`, death summary in
  `HUD.show_game_over()`, retry / return-to-title.
- **Checkpoint:** a complete loop: Title → run → death summary → retry.

---

## Module 12 — Build diversity: items & synergies (the Isaac hook)
- Turn flat stat upgrades into an owned, stacking **item collection**.
- `PlayerController`: an `items` array + composable on-hit effect fields
  (`burn_dps`, `chill_factor`, `chain_count`, `execute_threshold`) and transform
  flags (`echo_level`, `whirlwind`, `twin_strike`).
- `EnemyBase.ignite()/chill()`: status effects the items drive (DoT + slow).
- `WeaponController._apply_hit_effects()`: burn/chill/chain/execute/twin run on
  every melee hit; `SlashWave.gd` is the Echo Blade's ranged, piercing wave (a
  *player* hitbox on collision layer 32, so it never hurts the player).
- **Synergies**: owning the right pair fuses (`_resolve_synergies()` →
  Plasma Arc / Glacial Echo / Cyclone / Soul Harvest), Vampire-Survivors style.
- `UpgradeManager`: items carry a `rarity` (common/rare/cursed) and `unique`
  flag; `UpgradeCard`/HUD item bar colour by rarity.
- **Checkpoint:** picks compound into emergent builds, not just bigger numbers.

## Module 13 — The run economy: gold, treasure & shops
- `gold` in `GameManager.run_stats` (in-run currency; `register_gold`/`spend_gold`).
  Kills and smashed props drop `GoldPickup` coins.
- `ItemPedestal.gd`: a code-built walk-up stand. **Treasure rooms** spawn three
  free pedestals — take one, the rest vanish. **Shops** (`RoomType.SHOP`) sell
  priced items with a **reroll** stand.
- **Checkpoint:** clearing rooms earns gold you spend on real decisions.

## Module 14 — Risk & reward: the Forge Altar (Devil Deal)
- `RoomType.ALTAR`: a deal room offering power for a **max-HP** price (not
  corruption) — the run's signature gamble, à la Isaac's Devil Room.
- Sharpen the corruption curve so Overloaded is a knife's edge: +22% damage
  dealt but +40% taken, and more corrupted elites.
- **Checkpoint:** every floor forces a "how greedy am I?" choice.

## Module 15 — Active abilities ([E]) & rarity weighting
- A single active slot (`PlayerController.set_active_item`) with a charge bar:
  **Forge Pulse** (nova), **Phase Step** (blink + i-frames), **Blood Siphon**
  (drain-heal). Bound to a new `active_item` input (E).
- `UpgradeManager.get_choices` now does rarity-weighted sampling.
- **Checkpoint:** a panic button / build-defining active, found like any item.

## Module 16 — The professional layer: framing, pause, music
- **Scene transitions**: a `Transitions` autoload (a high-layer `CanvasLayer`
  fade-to-black, `process_mode = ALWAYS`, ignore-time-scale tweens) drives every
  scene change — no more hard cuts.
- **Pause menu**: Esc (`ui_cancel`) toggles `get_tree().paused`; the menu is built
  in code on the HUD with `process_mode = ALWAYS` so it works while paused
  (Resume / Restart / Return to Title). Guarded off during the upgrade screen and
  the death screen.
- **Ambient music**: `tools/generate_music.py` synthesises two seamless-looping
  pads (calm for menus, tense for the dungeon); `AudioManager.play_music()`
  crossfades on the Music bus and survives scene changes.
- **UI consistency**: the build list is a framed `PanelContainer`; the minimap
  gains a bordered panel, corridor connections (from `Dungeon.links`), and a
  pulsing current-room outline. Title/Hub get drifting forge-embers, a living
  title glow, button hover/press sounds, and a version tag.
- **Checkpoint:** the game opens, plays, pauses, and transitions like a finished
  product — not a prototype.

### Suggested commit checkpoints
One commit per module keeps the course diffable. Tag them
`m0-setup`, `m1-movement`, … `m11-framing` so students can check out any stage.

### Ideas beyond the prototype
Boss rooms, a meta-progression hub, weapon variety, controller support,
save/continue, real art & music, and a proper title/credits flow.
